# 收起态消息动画

本次为收起态内容切换的局部优化，沿用岛屿的字体、配色、宽度与消息入口。

- 设计目标：让短暂到来的消息轻柔地接替待办或专注任务，结束后自然恢复。
- 原文字上移 9px、160ms 淡出；新内容从下方进入，延迟 40ms、280ms 减速到位，并带有轻微模糊消散。恢复时方向相反。岛屿外框不因消息改变大小。
- 微信：现有微信图标 +「你收到了一条消息」。QQ：QQ 图标 + 好友名 + 消息。QQ 邮箱：邮箱图标 + 邮件主题摘要。好友名和消息分别省略，完整内容保留在无障碍标签中。
- 保留接收器原有预览时间（通常 5 秒），不新增消息队列。新到消息可以打断过渡；同一快照的重复渲染不会重播。更新较新的消息后，不再回放仍未过期的旧来源。
- 通知结束后恢复当前待办数量或当前专注任务，保留标题开关和像素字体。展开、边缘收起时立即清除动画残留；托盘隐藏期间不展示新预览。
- 尊重「减少动态效果」，并在动画结束事件缺失时清理旧内容。

## 验证

```powershell
node --test tests/message-preview.test.mjs tests/qq-notification-timing.test.mjs
pnpm build
pnpm dev
```

打开 `http://localhost:1420/tests/collapsed-message-animation.html?test=1`，运行真实 `IslandShell`、通知 Hook 和 Tauri 官方 IPC mock 的回归检查。覆盖三种来源、自动恢复、交错消息、动画打断、窄宽度、长内容、标题/像素字体、点击入口、展开/边缘收起/托盘隐藏与减少动态效果。检查应连续通过 3 次。

不带 `test` 参数可手动操作；`state=wechat`、`state=qq`、`state=qqMail` 可直达对应预览。测试页恢复自身修改过的存储偏好，不读取本机消息或调用原生应用。

本次只对该组件进行画面对比和交互自检，不做整页视觉重设计或独立评分。
