# QQ 邮箱接入

首版支持一个 `@qq.com` 邮箱，使用本机直连 IMAP，无需额外服务器或 Windows 通知访问权限，也不依赖 QQ 客户端运行。

## 首次连接

1. 打开 QQ 邮箱网页，在邮箱设置中开启 IMAP，按提示验证身份并生成授权码。具体设置位置以 QQ 邮箱当前界面为准；可在 [QQ 邮箱帮助中心](https://service.mail.qq.com/) 搜索「IMAP」或「授权码」。
2. 展开岛屿，点击消息按钮，选择「QQ 邮箱」。
3. 填写邮箱地址和授权码，点击「连接邮箱」。授权码与 QQ 登录密码不同，服务器地址和 TLS 参数由应用预设。

连接成功后每 60 秒检查一次收件箱，可手动刷新。列表展示最近 20 封邮件；未读总数来自整个收件箱，不限于这 20 封。邮件内容和附件不会下载，也不会改变邮箱已读状态。

首次连接、每次启动、暂停后恢复接收时只建立邮件基线，不弹出历史邮件提醒。此后新到且未读的邮件会在折叠岛上预览 5 秒，连续消息最多预览 10 秒；与 QQ、微信提醒按到达时间共享预览位置。展开、边缘收起或托盘隐藏时不主动展开、抢焦点。

折叠态的邮件图标显示未读数（最多显示 `99+`），点击进入邮箱面板。点击预览、列表项或「打开邮箱」会在默认浏览器打开 QQ 邮箱网页入口；浏览器未登录时需先登录，不保证直接定位到某一封邮件。

## 保存与恢复

- 授权码仅保存到 Windows 凭据管理器，服务名为 `com.focusd.island.qq-mail`，账号为邮箱地址；前端不读取已保存的授权码。
- `focusd-island-qq-mail-settings` 只保存邮箱地址和接收开关。邮件列表仅驻留内存，退出清空；下次启动从邮箱重新加载。
- 暂停接收保留凭据和本次运行的最近结果，恢复后重新建立基线。断开连接会停止检查、清空邮箱状态并删除凭据。
- 网络错误保留上次数据和同步时间，以 60、120、300 秒退避重试。授权码失效或 IMAP 未开启时停止自动重试，在表单中重新连接。
- 首版不支持多个账号、企业邮箱、自定义服务器、正文阅读、标记已读或发送邮件。

## 验证

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --lib qq_mail::tests
node --test tests/qq-notification-timing.test.mjs tests/message-preview.test.mjs
pnpm build
pnpm tauri build --no-bundle
```

协议测试使用模拟 IMAP 响应检查只读命令、中文邮件头、完整未读数、空收件箱、去重、UID 重置和过期请求。真实收件需要在本机界面输入有效授权码后验收；模拟协议、界面检查和构建不等同于真实邮箱连接成功。

## 本机验证记录（2026-10-19）

- Rust 邮箱模块 9 项测试、前端预览与角标 5 项测试通过；`pnpm build` 和 `pnpm tauri build --no-bundle` 通过。
- 独立 Edge 测试浏览器使用真实 React 界面和模拟 Tauri 边界，最终连续 3 轮通过。覆盖授权失败保留输入、暂停偏好恢复、断网保留列表、自动恢复后清除错误、三来源预览、展开或隐藏时不预览、最窄折叠宽度，以及连接过程中断开后清除输入并忽略旧响应；检查了普通与 2 倍像素密度截图。
- 界面复核发现并修复认证失败态主操作被裁切的问题，复核确认授权码输入、帮助入口和重连按钮完整显示。
- 本机到 `imap.qq.com:993` 的证书验证、TLS 1.3 握手和 IMAP 欢迎响应通过，未发送登录凭据。
- 未使用真实授权码，因此真实账号认证、收件、凭据实际写入与删除，以及原生托盘隐藏的完整交互仍需在桌面版验收。
- `imap 2.4` 的间接依赖 `imap-proto 0.10.2` 存在未来 Rust 版本兼容性警告，不影响当前构建；后续升级 Rust 时需关注。
